Como a informação viaja

Pense no fluxo como uma linha de transporte: a origem fornece os dados, o GitHub inicia o trabalho, o Python prepara os arquivos, o Supabase guarda a cópia publicada e o Streamlit mostra os números.

4 · ONDE FICA
Supabase Storage
Bucket privado metalforte-private

Guarda a base publicada, metas, estoque, indicadores e o estado da carga.

Exemplos: bases/metalforte_base.csv.gz e etl/latest.json.

5 · QUEM MOSTRA
Streamlit
App comercial METALFORTE 360

app.py, src/data.py e src/operational_dashboard.py leem os arquivos publicados.

O app não coleta no TOTVS: mostra a base já preparada.

Resumo em uma frase: TOTVS/GoodData → GitHub Actions chama o Python → Python publica no Supabase → Streamlit lê e apresenta. Se uma etapa falhar, o histórico de execução fica no GitHub Actions e o resumo sanitizado do andamento fica em etl/latest.json.

Quando muda o código do aplicativo? Alterações em app.py ou src/ vão para a branch main do repositório. O Streamlit Cloud busca/deploya essa versão; isso é uma publicação de código, separada da carga horária de dados.
E o HTML publicado no GitHub Pages? É outro caminho opcional: o workflow .github/workflows/publicar-command-center-html.yml publica arquivos da pasta web/ quando há alterações nessa pasta em main, ou quando alguém o dispara manualmente. Ele não é o app Streamlit.
